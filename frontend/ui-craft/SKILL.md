# UI Craft

项目已有组件、token、lint 和平台规范时以代码为准；本文件补它们表达不了的品味和默认取值。

## 品味

好看现代 = 克制的骨架 + 一个有分量的焦点 + 到位的细节。每屏只有一个视觉焦点，由真实内容或真实交互充当（数据、预览、作品、主输入），字号、体积、彩度和最用心的动效都给它；导航、控件、列表保持扁平克制。减法只删骨架上的噪音，不删焦点与信息。界面显得素、空、普通时，先加强排版层级、换上真实内容、把焦点做足，不加装饰、标签或卡片。焦点需要特效或成品动效件时，按 ui-picks 选库移植。

### 标签与页眉

以下是生成界面最常见的噪音，默认都不加：

- 标题上方的小号大写标签（eyebrow / kicker）。
- 给每节或每张卡加的分类、编号、状态小标签与徽标（01/02/03、「推荐」「NEW」）。
- 页面顶部重复导航当前项的页眉与副标题；Tab 列表常驻可见时，panel 里重复 tab 名的标题。

标题直接说内容，层级靠字号、字重和间距。标签只在承载用户需要区分的真实状态时出现（未读、失败、已过期）。导航在当前断点被隐藏、页面可经深链独立打开或页面很长时，才显示一个简短标题；省掉可见标题的内容区用 `aria-labelledby` 或准确的 accessible name 保持可定位，文档 `<title>` 随视图更新。

### 其他模板痕迹

渐变文字、默认玻璃拟态、无限等尺寸 Card Grid、无业务依据的大数字 Hero、统一米黄色背景、每段相同的入场动画、只为隔开区块而画的分割线和卡片。目标写法：用间距和对齐分组，动效预算集中给焦点。

## 开工

1. 读现有 Button、Input、菜单、Dialog、token 和一个相邻页面，全局尺寸沿用项目值。
2. 定主要输入（`pointer`、`touch`、`hybrid`）和一个默认密度（`compact`、`comfortable`、`touch`）。组件因业务例外时用语义变体承载。窗口变宽时增加内容、列或面板，控件尺寸固定。原生桌面应用用 AppKit、SwiftUI、WinUI 等系统控件尺寸，下表供 Web、Electron 和自绘界面。
3. 新建或大改时，先从请求、README 和代码定主要用户与核心任务；每页一个主要任务，定好层级与焦点再选 Card、分栏、侧栏或长页结构。没有既有品牌时选一个明确视觉方向，直接落到配色、字体、间距和表面层级。

## 密度与控件尺寸

项目没有设计系统时的默认值，平台规范优先：

| Profile | 典型场景 | Button / Input | Icon button | Row | Label | Icon | 水平 padding |
|---|---|---:|---:|---:|---:|---:|---:|
| `compact` | 浏览器插件、桌面工具栏、数据密集工具 | 32px | 28–32px | 28–32px | 13px | 14–16px | 10–12px |
| `comfortable` | 普通桌面应用、设置页、Dialog | 36px | 32–36px | 36–40px | 14px | 16–18px | 12–16px |
| `touch` | 触屏或触控为主的混合设备 | 44px；Material 48dp | 44/48px | 44/48px | 14–16px | 18–20px | 16–20px |

- 紧凑桌面的常用操作不低于 28px；触屏命中区只给 `touch` profile，可见图形可以更小，扩展命中区互不重叠。
- Button、Input、Select 和相邻分段控件同高；图标按钮正方形；含图标按钮与纯文字按钮同高，文字与图标间距 6–8px。主 CTA 靠颜色、位置和层级突出，不靠加高。
- 密度由一套 token 或 variant 控制（`control-height`、`control-padding-x`、`icon-size`），全部组件共用。
- 同心圆角：`outer radius = inner radius + padding`；两层间距超过 24px 时视为独立表面，各自取值。

## 排版与间距

| 用途 | `compact` | `comfortable` |
|---|---:|---:|
| 正文 | 13.5–14px | 14–15px |
| 控件、菜单、条目标题 | 13px | 14px |
| 次要说明 | 12–13px | 12.5–13.5px |
| 非关键元信息 | 11.5–12px | 12px |

- 关键标签、状态和操作文字不小于 12px；控件嫌大时缩控件，字号不动。
- CJK 小字号用更高行高并实机看；字重靠字体本身，不靠抗锯齿调粗细。
- 4px 间距尺度；2、6、10px 只用于图标或光学校准。相关内容紧，分组之间松。
- 动态数字用 `tabular-nums`；标题 `text-wrap: balance`，短描述 `text-wrap: pretty`。
- 选字体、字阶、行高字距、换行截断与混合方向见 `reference/typography.md`。

## 视觉层级

- 先用间距和对齐分组。数据表、设置组、可调整面板等需要明确边界时，用 1px 低对比分割线；分割线由内容语义决定。
- Card 只包裹真正独立、可操作的内容，只有一层。
- 普通 Card 用中性边界；状态或类别由 Badge、图标或文字表达。单侧彩色强调边只用于有提示语义的 Callout 或 Alert，颜色走共享语义 token。
- 表面需要表达"可抬起"时用 shadow-border token；只表达分隔用 1px 线。分割线、表格边界、输入框轮廓、选中态和 focus ring 保持真实 border，密集列表的行用分割线。

```css
:root {
  --shadow-border:       0 0 0 1px oklch(0 0 0 / .06), 0 1px 2px -1px oklch(0 0 0 / .06), 0 2px 4px 0 oklch(0 0 0 / .04);
  --shadow-border-hover: 0 0 0 1px oklch(0 0 0 / .08), 0 1px 2px -1px oklch(0 0 0 / .08), 0 2px 4px 0 oklch(0 0 0 / .06);
}
```

- 半透明 ring 适应任意背景，`box-shadow` 不占布局，hover 加深不推动周围元素。暗色下三层黑影看不见，退成单层白 ring `0 0 0 1px oklch(1 0 0 / .08)`，hover `.13`。`forced-colors: active` 会把 `box-shadow` 置为 `none`，靠阴影表达边界的表面在该媒体查询里补 `border: 1px solid`。
- 图片需要边界时加 1px 纯中性描边：亮色 `oklch(0 0 0 / .1)`，暗色 `oklch(1 0 0 / .1)`；带色相的近黑叠在图片边缘像脏污。
- 可滚动或折叠区域给出可见提示：露出下一项的一部分、边缘渐隐或计数。
- 布局按最长文本设计：定宽容器配 `min-width: 0` 和明确的换行或截断策略，截断后原文仍可获取。
- Sticky 操作只给高频、跨长列表仍需可见的动作，并让出内容、键盘焦点和小窗口视口。

## 空态与渐进披露

界面由内容挣得（Getting Real「The Blank Slate」；NN/g《Designing Empty States in Complex Applications》）。

- 容器为空时，只对已有内容才有意义的控件（搜索、筛选、排序、计数、批量操作、依赖既有内容的次级入口）等内容出现后再渲染，位置与最终布局一致。整屏让给一个居中引导：一句状态 + 一句下一步 + 1（最多 2）个此刻就能完成的动作；此刻走不通的能力写成一句预告。
- 加载中留白，数据到达再决定空态或内容。失败态与空态分开，失败可重试。
- 空态文案说清"还没有"与"怎么开始"，用中性色和常规图标。插画先用产品已有品牌图形；确需生成时按产品语气（gpt-image），统一光影与配色。呼吸、漂浮动效只在语气支持时用。
- 有合理缺省值的可选字段收进「添加 X（可选）」显式展开，展开后保持展开：双向折叠会把已填但非法的值藏起来。数量区间、格式要求等硬约束以紧凑形式常驻。
- 机制解释、候选来源、玩法等教学说明收进标签旁的问号 Toggletip；错误、门槛、后果持久可见。placeholder 或禁用态提示已承担"下一步"时，空内容区留白。
- 低频可选输入默认收成 icon-only 或一行入口，点开出输入框（autoFocus），失焦且为空时收回；有内容时保持展开。必填项常驻。

## 文案与交互语义

- Button 与链接写具体动作或目的，脱离相邻正文仍能理解；上下文已唯一确定对象时省略对象名。短标签、单句描述和按钮文案省略尾句号。
- 设置项的名称和描述写"打开后会发生什么"，用肯定句。中英文案保持语义、阈值和数量一致；只有措辞本身是需求时才用测试锁定。
- 每个交互组件实现适用的 default、hover、focus-visible、active、disabled、loading、error、success 状态。Web 自定义控件写 `cursor: pointer`（Tailwind v4 preflight 把 button 设回 `default`）；原生桌面控件遵循平台行为。
- 点击当前 tab、当前选项等幂等目标，视图保持原样。
- 有选中项的列表打开时让当前项进入可视区，用 `aria-current`、`aria-selected` 表达状态。
- Chat、日志、时间线打开时跟随最新内容；用户离开底部后暂停，回到底部恢复。阈值由行高或 token 决定，用事件和 observer 驱动。
- 复制按钮只在复制是高频任务时常驻；否则在 hover、focus-within 或上下文菜单中出现，键盘可达。
- 删重复页眉、同义标题与描述、显而易见的 helper、重复 CTA 时，先读 `reference/content-reduction.md`。
- 取舍 Label、Placeholder、输入图标、helper/error、Tooltip、Toggle、Banner、Toast 时，先读 `reference/forms-and-feedback.md`。其中三条是发布门，请求冲突时说明依据并实施最接近原意的安全替代：认证、地址、付款和多字段表单保留持久可见 Label；错误、安全影响、不可逆后果和完成任务所需信息持久可见；Toggle 等已有明确终态的控件，终态即反馈。

## 动效

- 动画预算与操作频率成反比：键盘快捷键、命令面板开合等每天上百次的操作即时切换；每天几十次的只留轻微反馈；delight 只给低频或首次体验。
- 每个动效说得出用途：反馈、空间连续、状态变化、避免跳变、讲解。高频处"好看"不算用途。
- 位移、缩放和进出场只动 `transform`/`opacity`；可被快速重复触发的用 transition 或 spring（从当前值中断重定向），不用 keyframes。
- 反馈 120–180ms，UI 动效不超过 300ms；标志性动效 280–700ms，只出现在少数低频、高意图组件。
- token、进出场配方、按下反馈、弹簧、路由转场、clip-path 配方和实现坑见 `reference/motion.md`；拖拽、swipe、bottom sheet、carousel 见 `reference/gestures.md`；图标选型、描边、状态与图标动效见 `reference/icons.md`。

## 审查输出

1. 用真实最坏数据压测，从数据入口替换而不改组件：长名（`Aleksandra Wiśniewska-Kowalczyk`）、无空格长邮箱、单字名（`Jo`）、缺失的可选字段与头像、计数 0 / 1 / 1284、超长译文（德语复合词）、CJK、RTL、emoji 开头的名字、1000+ 行列表；在真实容器宽、320px、200% 缩放和暗色下看。常见签名：头像被挤成椭圆 → `flex-shrink: 0`；文字撑破容器 → 文本列 `min-width: 0`（grid 用 `minmax(0, 1fr)`）；邮箱、URL 溢出 → `overflow-wrap: anywhere`；"1 members" → `Intl.PluralRules`；裸数字 → `Intl.NumberFormat`；文件名、路径、哈希末尾才有区别 → 中间截断；金额、日期等要比较的值不截断。完成标准：每个渲染出的值都试过最坏值。
2. 按问题分组输出 Before / After，只列有证据的问题，优先修 token 和共享组件。每条标严重度：`HIGH` 阻断任务、误导用户、隐藏内容或控件；`MEDIUM` 明显损害理解、效率或一致性；`LOW` 局部打磨。同一根因合并为一条，列出全部位置。一次最多 15 条。
3. 附「考虑过但否决」2–5 条：位置、候选改法、否决理由（项目刻意如此、证据不足、改了只增加复杂度都算）。
4. 验证分两栏：已验证（命令或操作与观察结果）和未验证（原因）。
5. 结论三选一：有 `HIGH` 则 `Block`；只剩 `MEDIUM`/`LOW` 则 `Needs changes`；无待办且覆盖已验证才 `Approve`。审查默认只读。

## 完成标准

每屏的焦点已指认并做足；「标签与页眉」「其他模板痕迹」已逐项对照目标界面；密度 profile 落在 token 或共享组件上，而非逐处覆写；动效已录屏或逐帧看过起点、终点、中途反向和 reduced-motion。
