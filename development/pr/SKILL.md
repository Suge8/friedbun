---

PR 描述写给审阅者快速看懂并决定能不能合：

- **改动**：先给一个最小视图，再配一两句话。改了调用关系画调用树，改了结构画文件树或 diff 草图，改了逻辑写几行伪代码，改了界面放改前改后截图；纯文案、纯文档改动直接写话。
- **证据**：只写 CI 看不到的——bug 改前复现、改后消失的那条测试或操作，界面截图，手动走查结果。CI 会跑的检查不复述。
- **未验证**：没覆盖到的及原因。
- **合并风险**：含迁移、删数据、改对外接口这类回不去的改动时，写一行能否回退与影响面；普通改动省略。

调用树草图示例：

```diff
 submitForm
   createSession
+    expandSkillMention
   navigateToSession
```

只写最终行为，不提 diff 之外的取舍和从未合入的状态。项目有 PR 约定时以项目为准。
