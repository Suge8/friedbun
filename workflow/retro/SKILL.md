用户要求**复盘**。目标是改进 agent 的**环境**——引导文件、检查链、工具、信息通路——让后续运行更顺，而不是评价这一次的结果。

## 步骤

1. 读 `../../development/writing-for-agents/SKILL.md`，产出文档改动时按它写。

2. 读会话一手记录。Pi 会话按工作目录存于 `~/.pi/agent/sessions/<目录路径编码>/*.jsonl`，用户未指定则取当前会话。完成标准：每个工具调用与其结果都已过目，而不是只看对话摘要。

3. 按下列类别逐类核对，找候选。每个候选附会话中的证据（发生了什么、耗了多少轮）。

   - **导航**：agent 找一个文件或事实花了多轮。是否缺一条 AGENTS.md 里的指针，或指针措辞太弱没触发？
   - **自动检查**：agent 犯的错本可被 lint hook、类型检查或接缝上的测试捕获。参考 `../../development/better-test/SKILL.md` 判断值不值得加。
   - **引导蔓延**：AGENTS.md 或 skill 里有 agent 默认就会做的**无操作**指令、已过时的**沉积物**、同一规则的第二份副本。候选是删除或收口到单一事实源，不是补写。
   - **工具经济**：昂贵或高噪声的工具调用——大文件整读、重复搜索、本该委派给子代理的长任务。
   - **信息通路**：agent 需要却拿不到的信息——dev server 日志、第三方服务只读访问、被忽略的环境事实。

4. 按严重程度排序呈现候选，每条给出建议改动与代价；等用户挑选后再动手。

## 参考

引导材料在本仓库的落点，避免写错位置：

- `AGENTS.md`：每回合都在上下文里，只放指向其他文件的导航指针。
- Skill：description 常驻上下文，正文按需加载；规则与参考资料放这里。手动触发的 skill 加 `disable-model-invocation: true` 并登记到 `../../AGENTS.md` 手动表。
- 项目 `docs/`：通过指针触达的参考资料。先找已有文档，再考虑新建。
- 环境本身（配置文件、脚本、`--help`）是事实源；文档只缓存查看不到的东西。
