# 清理与审计分工

分工的理由是上下文：每条判决都要读测试、被测 owner、调用方、重叠测试和历史，跨几个模块后单个会话装不下。编排者只保留全局视野，负责跨片裁决。

## 切片

按生产 owner 模块切，每片包含该模块的测试文件。多个模块共用的测试支撑代码（fixture、helper、全局 setup）不分给任何工人，由编排者最后统一处理，保持每个文件只有一个写者。

## 第一波：只读判决

所有工人同一波发出，彼此无依赖；删不删取决于对合同的判断，用与编排者同级的实现角色。每张任务卡写明：

- 片内路径与用户授权模式（审计或清理）；
- 读本 skill 的 SKILL.md，按价值门与判决规则逐条判；
- 本波只读，不改文件；
- 交回：逐条判决，格式同 SKILL.md 的报告；另附**跨片线索**——疑似和其他片重复证明的合同（测试名、合同一句话、疑似重复的位置），没有写"无"。

## 收口

1. 裁决跨片线索：同一合同保留最低可靠边界上的那条，其余改判 DELETE 并补证据。
2. 抽查每片的 KEEP 举证和 DELETE 证据，不全的退回原工人补齐。
3. 审计模式到此合并报告交给用户。

## 第二波：清理

清理模式下，能续派就让原工人按定稿判决只改自己片内的文件，并跑片内最窄验证；不能续派就派新工人，任务卡附定稿判决。各片完成后，编排者删除共享支撑代码和跨片的测试专用接缝，跑受影响验证，按 SKILL.md 出总报告。
