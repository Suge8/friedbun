# 逻辑原型

一个自包含的 HTML 文件，任何人点按钮就能驱动状态模型。用于业务逻辑、状态转换、数据形状这类纸面上看着合理、走过真实案例才露馅的问题。接收者包括设计师、PM、领域专家，所以页面用他们的语言，不用代码的语言。

## 流程

### 1. 写下问题

动手前写下要原型化的状态模型和问题，作为演示顶部可见的一段介绍，用户随时能对照检查。

### 2. 逻辑隔离成可移植的纯模块

回答问题的逻辑放在单独的 `<script>` 块里，写成小型纯模块，日后可原样提取进真实代码库。页面是一次性的，这个模块不是。

按问题选形式，而不是按哪种最好接到页面上：

- **纯 reducer** `(state, action) => state`：action 是离散事件、state 是单个值。
- **状态机**：显式状态与转换；“此刻哪些 action 合法”本身就是问题的一部分。
- **一小组纯函数**，作用于普通数据：没有隐式当前状态，只有转换。
- **带清晰方法面的类或模块**：逻辑确实持有持续的内部状态。

模块不碰 DOM、`document`，按钮处理器不伸进它内部；页面调用它，没有东西反向流入页面。

### 3. 构建 HTML 文件

一个文件，普通 HTML/CSS/JS，全部内联；不用框架、bundler、server，双击或邮件附件都能打开运行。

按钮、状态字段、说明全用领域语言（“提交审批”“已驳回”，而不是 `dispatch(SUBMIT)`、`status: 2`）。从上到下：

1. **标题和一行说明**：这个演示让你探索什么（第 1 步的问题）。
2. **当前状态**：带标签字段的可读面板（不是原始 JSON），每次点击后重新渲染；对非开发者有帮助时标出刚变化的字段。
3. **自由操作按钮**：每个 action 一个，始终可点，任意顺序试探模型。
4. **引导式演练**：每个场景一个标签页，写一段通俗的情境与要观察什么，下面是按顺序要**按的按钮**；每步是真实按钮，点击执行 action 并进到下一步。开始演练时重置到已知初始状态，保证每次运行一致。

场景选纸面上难推理的：正常路径、棘手边界、尝试本应非法的操作。

样式从简：一种强调色，无动画。

### 4. 交付

把文件发给用户或替他打开。对方说“等等，这不应该能做到”或“我以为 X 会不一样”，就是想法里的 bug；要新 action 或场景就加上。
