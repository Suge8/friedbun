用户要求**复盘**。目标是改进 agent 的**环境**——引导文件、检查链、工具、信息通路——让后续运行更顺，而不是评价这一次的结果。

## 步骤

1. 读 [writing-for-agents](../../development/writing-for-agents/SKILL.md)；改动落点（AGENTS.md、skill、项目 docs）和写法都按它。

2. 读会话一手记录。Pi 会话按工作目录存于 `~/.pi/agent/sessions/<目录路径编码>/*.jsonl`，用户未指定则取当前会话。完成标准：每个工具调用与其结果都已过目，而不是只看对话摘要。查会话与用量的统计先用 [session-data](../../operations/session-data/SKILL.md)，不现写脚本扫原始文件。

3. 按下列类别逐类核对，找候选。每个候选附会话中的证据（发生了什么、耗了多少轮），并过一道筛：换一个 agent 认真重做，这个代价还会出现吗？不会就是这一轮的偶然失误，不列为候选；逐类核对后没有候选就直说。

   - **导航**：agent 找一个文件或事实花了多轮，或照着过时文档走了弯路。是否缺一条 AGENTS.md 里的指针，或指针措辞太弱没触发？文件之间有没有隐藏依赖（改了甲必须同步改乙，却没有任何地方写明或检查）？
   - **自动检查**：agent 犯的错本可被 lint hook、类型检查或接缝上的测试捕获。先读仓库已有的检查入口（lint/check 脚本、提交钩子、CI 工作流）：已有但没接上或已坏的检查，候选是接上或修好它，不另造。按 [better-test](../../development/better-test/SKILL.md) 判断值不值得加。同类纠正出现两次，按 架构消除 → 类型 → lint（报错写明该用什么）→ 测试 → 文档 的顺序处理；机械型违规（固定写法、禁用 API、导入形态、文件位置）一律做成检查，不写成规则；新检查要在一个真实历史错误上证明会变红。仓库没有提交钩子也没有 CI，本身就是一条发现。
   - **审查漏判**：审查放过了本该拦下的错。机械型的归入自动检查；只能靠判断的，写进审查者会读的项目约定，并附这次漏掉的实例；约定里已有却没起效的那条，候选是改清楚或删掉。规范由审查者执行而不压给实现方：实现方要探索、写码、调试，上下文最紧，审查者只看 diff。
   - **引导蔓延**：AGENTS.md 或 skill 里有 agent 默认就会做的**无操作**指令、已过时的**沉积物**、同一规则的第二份副本。候选是删除或收口到单一事实源，不是补写。常驻文件里的编码规范类指令，候选是移到审查约定或做成自动检查。
   - **工具经济**：昂贵或高噪声的工具调用——大文件整读、重复搜索、本该委派给子代理的长任务。自建 CLI 或 MCP 的输出本身费 token 的，候选是改工具的输出，不是教 agent 绕开。
   - **信息通路**：agent 需要却拿不到的信息——dev server 日志、第三方服务只读访问、被忽略的环境事实。

4. 按严重程度排序呈现候选，每条给出建议改动与代价；等用户挑选后再动手。
