# 配色

只保留模型默认不会用对的取值与做法。

## 用法

- 沿用项目既有的语义 token 和色值写法；一致的 hex/RGB 体系里修单个颜色时，不引入第二种表示法。迁移到 OKLCH 是独立任务。
- 一色一义：交互色（及其 ±15° 内的色相）只给可点的东西；装饰性标题用交互色相，用户会去点它。
- 按角色命名并按角色使用 token；缺角色就加 token，不借一个碰巧数值合适的（分隔线 token 不当文字色）。
- 用实心底色表达主次时，一个决策上下文里只有一个实心主动作，同级动作保持中性。颜色放在背景上而不是文字上：彩色文字的中性按钮读起来像链接。选中态（当前 tab、选中分段）可以给字形和文字上强调色，那是状态不是强调。项目已用别的方式表达主次时保留原有层级。
- 颜色含义随地区变：中国金融界面红涨绿跌，与西方相反；白色在东亚部分地区是丧色。颜色承担含义（金融、状态、告警）时，涨跌色做成按 locale 取值的 token。

## 调色板

- 多色相调色板用相同的 L 和相同的 **chroma 百分比**（占该色相在该明度下最大彩度的比例），不用相同的绝对 C：同一明度下各色相的最大彩度差很多。L = 0.5 的 sRGB 里紫（H≈285）可到 C≈0.29，红橙（H 0–30）≈0.20，青（H≈195）只有≈0.09；峰值色相随明度移动（L 0.7 洋红最高，L 0.9 绿最高），青始终最低。统一绝对彩度只能迁就色域最窄的色相，其余色相跟着发灰。
- 生成单色阶：`minL = max(0.05, baseL − 0.4)`，`maxL = min(0.95, baseL + 0.4)`，L 在两端之间均分；每一档 `C = chroma% × maxChroma(L, H)`，两端彩度自然降低。
- 色阶各档色相漂移超过 10° 就肉眼可见；HSL 色阶会漂（`hsl(240,…)` 浅档偏紫约 16–18°），用恒定 OKLCH 色相重建。
- 彩度超出色域时保持 L 和 H、降低 C；P3 增强放在 `@media (color-gamut: p3)` 里，sRGB 值作默认。
- OKLCH 写法：L、C 三位小数，H 至多三位，去尾零，`-0` 写 `0`；alpha 用斜杠 `oklch(L C H / a)`。Tailwind v4 的 `@theme` 用 OKLCH 值。

## 暗色与高对比

- 暗色以亮色调色板为起点交换语义角色，再单独调暗色下的彩度和明度；不机械反转色阶。每一对前景/背景在两种外观下都重新测量。
- `prefers-contrast: more` 的变体让前景/背景明度差在默认基础上再拉开至少 0.15 L，再按 APCA 优选阈值复测。
- 半透明表面（`backdrop-filter` 页头、遮罩）上的颜色随下方内容变化：在能出现的最亮和最暗内容上各测一次，或把表面做得足够不透明。

## 对比度

对比度总是测前景与它实际渲染所在的背景。检查不过时报告这对颜色、实测值和差的阈值，不擅自改色；用户要求修复时先调 L，尽量保持 C 和 H，再复测渲染结果。

| 内容 | APCA 最低 | APCA 优选 |
|---|---:|---:|
| 正文（成段文字） | Lc 75 | Lc 90 |
| 非正文文字（标签、标题） | Lc 60 | Lc 75 |
| 大字（≥36px） | Lc 45 | Lc 60 |
| UI 组件、禁用与 placeholder 文字 | Lc 30 | — |

- APCA 的 Lc 带符号（正为浅底深字），比较时取绝对值；非文本元素可辨认的绝对下限是 Lc 15。正式声明 WCAG 2.x 合规时仍按 WCAG 比值测。
- 明度差速查（正文，目标 |Lc| ≥ 75）：浅底 L > 0.9 时前景 L < 0.35；深底 L < 0.25 时前景 L > 0.9。两边不对称是因为 APCA 区分极性；只作估计，以实测为准。
- 中性底上 L > 0.73 才算浅底、用深字；0.6–0.73 看起来已经浅了，但白字得分仍明显更高。
- 中等明度的底封顶了可达对比度：L 0.75 的底上纯黑字也只有约 Lc 60，正文需要接近两端的底色。
